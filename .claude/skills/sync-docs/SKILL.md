# 문서 동기화 (sync-docs)

마지막 문서 갱신 이후의 작업을 모아 아래 문서들을 일괄 업데이트한다.
각 단계는 "실제로 바뀐 게 있을 때만" 손댄다 — 변경이 없으면 건너뛰고 그렇게 보고한다.

## 0. 변경사항 파악 (먼저)
- `git log` 로 최근 커밋들을 보고, PROGRESS.md의 마지막 기록 날짜 이후 무엇을 했는지 정리한다.
- `git status` 로 미커밋 변경도 확인한다.
- 오늘 날짜를 절대 날짜(YYYY-MM-DD)로 확정한다. 문서엔 "어제/지난주" 같은 상대 표현을 쓰지 않는다.

## 1. CLAUDE.md
- "구현 단계 현황" 표의 Phase 상태(✅ 완료 / 🚧 진행 중 / ⏳ 대기)를 실제에 맞게 갱신.
- 기술 스택·디렉토리 구조·API 규칙에 바뀐 게 있으면 반영.

## 2. PROGRESS.md  (※ gitignore — git에 안 올라감, 로컬 기록용)
- 맨 아래에 오늘 날짜 섹션을 추가한다. 완료한 작업 + "다음 작업"을 적는다.
- 기존 기록 형식(날짜 헤더 → Phase별 체크/설명)을 따른다.

## 3. docs/architecture-decisions.md
- 이번에 새로 내린 설계 결정이 있으면 추가한다.
- 형식은 기존 항목과 동일: *상황 → 선택 → 이유 → 아쉬운 점*. 산문체, 과한 불릿·이모지 지양.
- 단순 기능 추가는 넣지 않는다. "왜 이렇게 했는지" 설명거리가 있는 결정만.

## 4. 노션 (Notion MCP)
- **프로젝트 페이지** `3665632d-6342-8029-8ca3-e7c0415c8d92`
  - "🚦 현재 진행 상황" 표의 Phase 상태를 CLAUDE.md와 일치시킨다.
- **PROGRESS 페이지** `3685632d-6342-8176-b05d-f1441bd25bf5`
  - "현재 진행 상황" 체크리스트 토글, "진행 기록"에 날짜 항목 추가, "다음 할 일" 갱신.
- **TIL DB** (data source `collection://85306aeb-7bcc-4143-ac68-a48b805141bb`, DB 페이지 `139c5435bc4d48c585bdc88d625a26f3`)
  - 이번에 새 TIL이 생겼으면 행을 추가한다. 속성: 제목 / 태그 / 작성일 / 상태(초안·정리완료·블로그발행).
  - 본문은 증상→진단→원인→해결→교훈→블로그 각도 구조.
- update_content 전에는 fetch로 현재 내용을 확인해 old_str을 정확히 맞춘다.

## 5. 마무리 (커밋 / push)
- 바뀐 파일을 커밋한다. **커밋 메시지에 Co-authored-by 줄을 넣지 않는다.**
- PROGRESS.md는 gitignore이므로 커밋 대상에서 빠지는 게 정상이다.
- **push는 항상 사용자에게 먼저 확인하고 진행한다.** push 전 remote가 `github.com/wooqqq/curio`, author가 개인 계정 `wooqqq / sge0225@naver.com`인지 확인한다 (회사 계정으로 나가면 안 됨).
